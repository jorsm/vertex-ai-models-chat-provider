# NNNN — Short name

## Goal

What will be true when this is done, in two or three sentences.

## Context

The evidence that makes this necessary: what happens today, with file references and numbers.

## Non-goals

What this spec deliberately does not change, even if it is nearby.

## Decisions

Choices already made that the implementation must respect, and who made them.

## Behavior and invariants

The externally observable behavior after the change, and the rules that must keep holding.

## Declared divergences

Only if the change touches a transport: which behaviors may differ between direct and proxy, and why. Delete this section otherwise.

## Deliverables

Numbered items (D1, D2, …), each small enough for one PR or one commit.

## Acceptance checks

How a reviewer verifies each deliverable: commands to run, tests that must pass, behavior to observe. Each check names the failure it would catch.

## Open questions

Anything still undecided. A spec moves to `approved` only when these are answered or explicitly deferred.
